# الفيزياء والكيمياء — الصف السابع (منصة تعليمية تفاعلية)

منصة Next.js (App Router) + React + TypeScript + PostgreSQL (Drizzle ORM) لتقديم
دروس الفيزياء والكيمياء للصف السابع (المنهاج السوري)، مع دروس تفاعلية،
مختبرات، واختبارات إلكترونية. اللغة العربية (RTL) وخط Cairo، والرموز العلمية عبر KaTeX.

## المتطلبات

- Node.js 22+
- PostgreSQL للوظائف التي تحفظ البيانات (ملفات الطلاب، حفظ تقدّم الدروس)

## التثبيت

```bash
npm install
cp .env.example .env   # ثم اضبط القيم حسب بيئة النشر
```

## قاعدة البيانات والـ migrations

إعداد Drizzle Kit في `drizzle.config.ts` لا يحتوي على أي عنوان قاعدة بيانات ثابت أو
خاص ببيئة بعينها؛ يُقرأ `DATABASE_URL` من بيئة التشغيل (أو من ملف `.env` محليًا
عبر `dotenv/config`) — وهو نفس المتغيّر الذي يستخدمه التطبيق في `src/db/index.ts`.

ملفات الـ migrations محفوظة في `drizzle/migrations/` وتُولَّد مباشرة من
`src/db/schema.ts`؛ أي تغيير لاحق على الـ schema يتطلب تشغيل `npm run db:generate`
من جديد لإضافة ملف migration جديد (لا تُعدَّل الملفات المولَّدة سابقًا يدويًا).

خطوات إعداد قاعدة بيانات جديدة من الصفر:

```bash
cp .env.example .env            # اضبط DATABASE_URL على قاعدة PostgreSQL فعلية
npm run db:generate             # (اختياري) تأكيد أن لا تغييرات غير مولَّدة في الـ schema
npm run db:migrate              # تطبيق الـ migrations على القاعدة الفعلية
```

`db:generate` و`db:check` يعملان بمقارنة ملفات الـ schema مع ملفات الـ migrations
المحفوظة محليًا فقط، لذا ينجحان حتى بدون `DATABASE_URL` (مناسبان للتحقق في CI
أو في بيئة بلا قاعدة بيانات). أما `db:migrate` فيحتاج اتصالاً فعليًا بقاعدة
PostgreSQL حقيقية عبر `DATABASE_URL`؛ وعند غياب `DATABASE_URL` يفشل فورًا برسالة
واضحة من Drizzle Kit (`Please provide required params for Postgres driver: [x] url: ''`)
دون أي محاولة اتصال فعلي ودون استخدام أي عنوان افتراضي.

**تنبيه — قاعدة بيانات جديدة فقط:** ملف الـ migration الأول
`drizzle/migrations/0000_init_schema.sql` هو migration **إنشائي** (`CREATE TABLE`).

- **قاعدة بيانات PostgreSQL جديدة وفارغة** (لا تحتوي أصلاً على الجداول
  `students`, `lesson_progress`, `quiz_attempts`, `project_authoring_rules`):
  يمكن تشغيل `npm run db:migrate` عليها مباشرة لتطبيق migration 0000 كما هو.
- **قاعدة بيانات تحتوي هذه الجداول مسبقًا** (من إعداد يدوي سابق أو من نسخة
  أقدم من المشروع): **لا يجوز** تشغيل `npm run db:migrate` عليها مباشرة؛
  migration 0000 سينفّذ `CREATE TABLE` من جديد وسيتعارض مع الجداول الموجودة
  فعلاً.
- في هذه الحالة الثانية يلزم أولاً اعتماد **baseline** مناسب: أي التحقق من
  أن بنية الجداول الحالية مطابقة تمامًا لما في `0000_init_schema.sql`، ثم
  اعتبار هذا الـ migration "مطبَّقًا مسبقًا" لدى Drizzle بدل تنفيذ الـ
  `CREATE TABLE` فعليًا عليه. هذا الاعتماد **ليس إجراءً تشغيليًا جاهزًا أو
  موثَّقًا ضمن P1-2** — هو خطة وإجراء منفصلان يجب تصميمهما وتنفيذهما بحذر لكل
  حالة على حدة (تختلف حسب أداة تتبّع الـ migrations وإصدارها)، ولم يُنفَّذ أو
  يُختبر هنا. **لم يُنفَّذ أي SQL يدوي ولم تتغيّر أي قاعدة بيانات فعلية** في
  إطار توثيق هذا التنبيه.

## متغيرات البيئة

تُضبط في بيئة الخادم (أو `.env` محليًا). **لا تُرفع أي أسرار حقيقية إلى المستودع.**

| المتغير | إلزامي | الاستخدام |
|---|---|---|
| `DATABASE_URL` | في زمن التشغيل | رابط اتصال PostgreSQL (Drizzle). تُستخدم قاعدة البيانات حالياً لإنشاء ملفات الطلاب، وحفظ تقدّمهم داخل الدروس (وقراءته في صفحة الطالب)، ولفحص الاتصال. لا تُستخدم لتخزين جلسات المعلم — المصادقة تعتمد على جلسات موقّعة (HMAC) ولا تُحفظ في القاعدة. كما أن حفظ محاولات الاختبارات الجديدة معطّل مؤقتاً حالياً (التسليم لا يُسجّل درجة). البناء لا يحتاجه: الاتصال يُنشأ عند أول استخدام فعلي، وعند غياب المتغيّر في زمن التشغيل يُرفض الوصول بخطأ واضح. |
| `TEACHER_PASSWORD` | نعم | كلمة مرور منطقة المعلم (6 أحرف على الأقل). تُحفظ سرًا في بيئة الخادم، ولا تظهر في الشيفرة أو الواجهة. |
| `TEACHER_SESSION_SECRET` | نعم | سرّ توقيع جلسات المعلم (32 حرفاً على الأقل، عشوائي). يُوقّع ويُحقّق منه رموز الجلسات بـ HMAC-SHA256. يجب ألّا يكون مشتقًا من كلمة المرور أو `DATABASE_URL`. عند غياب أي من المتغيّرين الأمنيين: لا تُصدر جلسات، ولا تُقبل، ويُرفض الوصول إلى منطقة المعلم (fail closed). |
| `STUDENT_SESSION_SECRET` | نعم | سرّ توقيع جلسات الطالب (32 حرفاً على الأقل، عشوائي، **مستقلّ** عن `TEACHER_SESSION_SECRET` و`TEACHER_PASSWORD` و`DATABASE_URL`). يُوقّع رموز جلسات الطلاب بـ HMAC-SHA256، وهي المصدر الوحيد لملكية بيانات الطالب. عند غيابه: لا تُصدر جلسات طلاب ولا تُقبل، ولا تُنشأ ملفات طلاب (fail closed). |

### جلسات الطالب وملكية البيانات (P1-4b)

- جلسة الطالب رمز موقَّع بصيغة `v1.<studentId>.<expiry>.<signature>` يُخزَّن في كوكي
  `student_session` بخصائص `HttpOnly` و`Secure` (في الإنتاج) و`SameSite=Lax` و`Path=/`.
- **ملكية بيانات الطالب تُشتق من هذه الجلسة وحدها**: لا من كوكي يرسله المتصفح،
  ولا من جسم الطلب. فالكوكي `student_id` القديمة (غير موقّعة) لم تعد تُقبل ولا
  تُقرأ، وتُمسح من المتصفح عند إنشاء ملف جديد.
- التحقق fail-closed: توقيع صالح + صلاحية سارية + UUID صحيح + **سجلّ موجود في
  قاعدة البيانات**. أي نقص ⇒ لا وصول.
- **الطلاب القدامى يحتاجون إلى إعادة تسجيل** (ملف جديد) لأن كوكيهم القديمة غير
  موقّعة؛ وسجلّاتهم التاريخية تبقى في قاعدة البيانات كما هي — دون حذف أو نقل
  أو تعديل.

تُقرأ متغيّرات الخادم في زمن التشغيل فقط (عبر `src/lib/env.ts`) كي لا تُخبز
قيمها في مخرجات البناء.

## النشر

النشر إلى بيئة إنتاج حقيقية يتم على **Vercel + PostgreSQL مُدار** عبر
`.github/workflows/deploy.yml` (فحص بناء واختبارات، ثم نشر تلقائي على `main`).
الخطوات الكاملة وأسماء متغيّرات البيئة وأماكن ضبطها في [`DEPLOY.md`](./DEPLOY.md).

## الهيكل

- `src/content/` — المحتوى التعليمي (الوحدات، الدروس، بنك الاختبارات).
- `src/db/` — اتصال قاعدة البيانات (Drizzle) وجدول الجداول.
- `drizzle/migrations/` — ملفات migrations المولَّدة من `src/db/schema.ts` (Drizzle Kit).
- `src/app/api/` — مسارات API.
- `src/lib/` — منطق الخادم (الأمان، الطالب، تصحيح الاختبارات).
- `tests/stage1/` — اختبارات الوحدة.
- `scripts/stage1-verify.mjs` — فحص التكامل HTTP.

# تشخيص: لماذا لم يظهر «أراجع وأختبر نفسي — الوحدة الأولى» للطالب

## الخلاصة في سطر واحد

بطاقة المراجعة **كانت مبنية ومنشورة بشكل صحيح على GitHub Pages منذ PR #20**، لكن صفحة
الوحدة التي تحتويها (`/units/unit-1/`) كانت **صفحة يتيمة (orphan page)**: لا يوجد أي
رابط إليها في التنقّل العام للموقع. فلم يكن الطالب يصل إليها أصلاً، وبالتالي لم يكن
يرى البطاقة — مع أن الاختبارات كلها كانت تنجح لأنها تفحص **الملف** لا **مسار الطالب**.

## ما نفته الأدلة (فرضيات التصحيحات السابقة)

كل الفرضيات التي بُنيت عليها PR #18 و#19 و#20 كانت **خاطئة**، وهذا ما يثبته الفحص الفعلي:

| الفرضية | الحكم | الدليل |
| --- | --- | --- |
| «آخر نسخة من main لم تصل إلى Pages» | ❌ غير صحيح | آخر نشر `github-pages` على `sha=98b39b8` (دمج PR #20) بتاريخ 2026‑11‑22T22:28Z، والحالة success |
| «التصدير المنشور لا يحتوي تعديل PR #20» | ❌ غير صحيح | أسماء حزم التصدير المنشورة (`3_xt3ukbhe-sj.js`، `3x9plxgv86pg_.js`، `3u4cyoi8wt_21.css`) **مطابقة حرفياً** لبناء محلي نظيف من نفس الـ commit |
| «HTML المنشور لصفحة الوحدة لا يحتوي البطاقة» | ❌ غير صحيح | البطاقة موجودة في `units/unit-1/index.html` المنشور، وفي `index.txt`، وفي `__next.units.$d$slug.__PAGE__.txt` المنشور أيضاً (أي تظهر حتى في التنقّل من جهة العميل) |
| «المشكلة في basePath / المسار / 404» | ❌ غير صحيح | كل الروابط تمرّ عبر `/Physics_Chemistry_7th/`، ولا استجابة ≥ 400، ولا خطأ JavaScript |
| «المشكلة في مكوّن عرض محتويات الوحدة أو الكشف التدريجي `.reveal`» | ❌ غير صحيح لهذه البطاقة | البطاقة **خارج** أي غلاف `.reveal` ومحتسب `opacity=1` و`visibility=visible` عند التحميل المباشر |
| «المشكلة في التخزين المؤقت للمتصفح» | ❌ غير صحيح | جلسة متصفح جديدة تماماً مع تعطيل الكاش (`Network.setCacheDisabled`) و`reload` قسري تُظهر البطاقة نفسها |
| «الرابط يعمل عند فتحه مباشرة» | ✅ صحيح | `curl`/`fetch` للصفحة يعمل، وفتحها مباشرة يعرض البطاقة |

## السبب الجذري المؤكد

`src/app/units/page.tsx` — صفحة «الوحدات الدراسية» التي يفتحها الطالب من الترويسة
(`/units/`) — كانت تعرض لكل وحدة:
- رأس الوحدة (العنوان والوصف) كنص **غير قابل للنقر**،
- ثم قائمة الدروس الخمسة كروابط مباشرة إلى `/lessons/<slug>/`.

ولم تكن تحتوي **أي** رابط إلى `/units/unit-1/`. والنتيجة المقيسة على التصدير الكامل:

```
عدد الروابط إلى /units/unit-1/ في كل صفحات الموقع: 2 فقط
  - out/quizzes/quiz-unit-1/index.html   (زر «العودة إلى الوحدة الأولى» داخل الاختبار)
  - out/units/unit-1/review/index.html   (زر «العودة إلى الوحدة الأولى» داخل المراجعة)
```

أي أن صفحة الوحدة تُفتح فقط عبر مسار غير بديهي: الطالب يذهب إلى «الاختبارات» ← يفتح
«اختبار الوحدة الأولى الشامل» ← يضغط «العودة إلى الوحدة الأولى». أما المسار الطبيعي
(الرئيسية ← الوحدات الدراسية) فيتوقف عند قائمة الدروس ولا يصل إلى صفحة الوحدة أبداً.

هذا يفسّر التباين الذي أرّق كل المحاولات السابقة:

> **البطاقة صحيحة ومنشورة، لكن لا أحد يراها — لأن الصفحة التي تعرضها غير موصولة بالموقع.**

ولذلك نجحت كل اختبارات CI: فحصت `out/units/unit-1/index.html` ووجدت البطاقة فيه،
ولم يفحص أي منها **كيف يصل الطالب إلى ذلك الملف**.

## الإصلاح (السبب الجذري فقط)

`src/app/units/page.tsx` — ربط صفحة الوحدة بما يسبقها في التنقّل:

1. **عنوان الوحدة صار رابطاً** إلى `/units/${unit.slug}`.
2. **زر «صفحة الوحدة»** ظاهر في رأس كل وحدة (وحدة ١–٤) بجانب شارة «دروس منشورة».

لم يُمسّ:
- قسم المراجعة نفسه (`src/components/review/*`، `src/content/unit1-review.ts`) — لا محتوى ولا أسئلة ولا محطات ولا تفاعلات.
- صفحة الوحدة `src/app/units/[slug]/page.tsx` — البطاقة كما هي، نفس الترتيب ونفس النصوص.
- الدروس الخمسة، دفاتر الطلاب، بنك الاختبار.
- إعدادات النشر (`next.config.ts`، `.github/workflows/deploy.yml`).

## اختبار انحدار يمنع التكرار

`tests/stage2/navigation-reachability.test.ts` — يفحص **الرابط** لا **الملف**:

- `/units/` ترتبط فعلاً بـ `/units/unit-1/` (وكل وحدات ١–٤).
- بطاقة المراجعة موجودة في صفحة الوحدة **وكآخر رابط في `main`**.
- اختبار الوحدة الشامل يسبق المراجعة.
- المراجعة لا تتكرّر (بطاقة واحدة فقط).

## التحقق البصري على الموقع المنشور مقابل البناء المحلي

**قيد بيئة العمل المهم:** بيئة التنفيذ في هذه الجلسة **لا تستطيع الوصول إلى
`calesteer-create.github.io`** (اتصال TLS مقطوع؛ `ERR_CONNECTION_CLOSED` في Chromium
و`SSL_ERROR_SYSCALL` في curl) — النطاقات المسموحة هي GitHub API فقط. لذلك:

- **تم** التحقق من المحتوى المنشور فعلياً عبر GitHub API/جلب الصفحات: تطابق أسماء
  الحزم المنشورة مع البناء المحلي **حرفياً**، ووجود البطاقة في HTML/RSC المنشور.
- **تم** التحقق البصري والتفاعلي في Chromium على **بناء محلي مطابق بايت ببايت**
  لمحتوى `98b39b8` المنشور (نفس أسماء الحزم = نفس ملفات CSS/JS).
- **لم يتم** فتح `github.io` مباشرة من Chromium داخل هذه البيئة. بعد دمج PR الجديدة
  ونشرها، يجب إعادة فحص القبول على الرابط الحقيقي للتأكد من وصول النشر.
